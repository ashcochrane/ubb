# 2026-07-28 billing-surface correctness (#132). PRE-LIVE LANE — see the matching
# block in oasdiff-err-ignore.txt for the api-v1-launch status and its rationale.
#
# The per-task floor snapshot is removed outright. It read a tenant-wide constant
# rather than the customer's own min_balance_micros, and compared it against a
# balance frozen at task start — so a mid-task top-up was invisible to it and it

# the correct scope for a wallet-wide fact:

GET /api/v1/tenant/config removed the optional property `default_task_floor_snapshot_micros` from the response with the `200` status

# 2026-08-09 the arrival-signals switch takes the name of what it governs
# (#246). PRE-LIVE LANE — map #137 constraint 1; ADR-0007 §5's "licence with one
# use remaining", spent deliberately rather than by accident, and the standing
# no-tenant-is-live note in docs/api-compatibility.md is what makes it
# available. Not a deprecation.
#
# A RENAME, NOT A REMOVAL. `live_counter_maintenance_enabled` takes this field's
# place with the same type, the same default and the same meaning; the column is
# carried across by RenameField (ADR-0007 §1) so no tenant's stored posture
# moves. oasdiff reports three findings because it compares property sets and
# has no way to see a rename — read the removals below together with the three
# additions the same diff makes, which are not breaks and so appear nowhere.
#
# WHY THE OLD NAME HAD TO GO. It named the arrival-time ingest lane. Slice 1
# (#192) deleted that lane and kept the switch, because the switch never was the
# lane's: it gates the synchronous live-counter debit and its crossing check,
# both reconciles' counter legs, and the upward repair — and it leaves the
# ingest path, the durable lane and the ack schema untouched in both postures.
# The conflation was not theoretical. `repair.py` was read under the lane
# meaning and #233 had to run as its own ticket to establish which reading was
# true; the answer (Ruling A2) changed what #234 was allowed to delete.
#
# WHY NOW AND NOT LATER. This is the whole timing argument and it is an act, not
# a date: before platform admission (#158's audit) a rename is coordinated by
# hand through these files; after it, ADR-0003 §4 governs with no judgement left
# — `deprecated: true`, a Sunset header, a dated changelog entry, an email and
# 90 days. The word would cost a deprecation cycle to fix.
#
# WARN, NOT ERR, AND THAT IS THE GATE'S VERDICT RATHER THAN A PREFERENCE. The
# ticket that raised this asked for the block to go in oasdiff-err-ignore.txt.
# `contract_gate.py --emit` classified all three findings WARN, and the two
# flags filter by level before matching text — so an entry in the err file would
# have suppressed nothing and quietly reported success.

# THE INLINE UNIT TOTAL, RETIRED — the column and every reader (#272, slice 2).
# The other half of the block in `oasdiff-err-ignore.txt`, which carries the
# ruling and the reason; these five findings are the same retirement on the four
# endpoints where the property was optional rather than required.
#
# BOTH DIRECTIONS, AND THAT IS THE POINT. Two of these five are REQUEST
# properties. The field was writable — a caller stated a nameless magnitude and
# UBB stored it whole — so retiring it had to close the door as well as the
# window. Leaving the request side open would have meant accepting a number with
# nowhere to put it, which is worse than refusing it.
#
# A CALLER LOSES NOTHING IT CAN STILL EXPRESS. `usage_metrics` carries the
# measured quantities by declared key and prices them; `provider_cost_micros`
# carries a cost the caller already knows. What is gone is only the third thing
# — one integer with no name, which could describe an input amount or an output
# amount but never both, and which is exactly why the split happened.
GET /api/v1/metering/customers/{customer_id}/usage removed the optional property `data/items/units` from the response with the `200` status
GET /api/v1/metering/usage/{event_id} removed the optional property `units` from the response with the `200` status
POST /api/v1/metering/usage removed the optional property `units` from the response with the `200` status
POST /api/v1/metering/usage removed the request property `units`
POST /api/v1/metering/usage/batch removed the request property `events/items/units`

# THE SECOND OPEN BAG, FOLDED INTO THE FIRST (#273, slice 2).
#
# A MOVE, NOT A RETIREMENT, and that is the whole difference from the block
# above. The unit total had nowhere to go, so it died. This one had somewhere:
# the same posting already carried an open bag, and the second one duplicated it
# under a name that advertised a capability the survivor deliberately does not
# have. A caller sends the same keys, to the same posting, under `metadata` —
# and `usage/migrations/0033_the_second_open_bag_folds.py` carries every
# existing value across so nothing already recorded is lost.
#
# WHY THE NAME GOES WITH THE CAPABILITY. The survivor is FILTERABLE AND
# READABLE, NEVER GROUPABLE. The retiring name promised grouping, and an
# unbounded free-text keyspace that can become a chart is one that can drive an
# invoice line label. Keeping the name would keep advertising the thing the
# design refuses. The keys inside are the tenant's own and are stored and
# returned exactly as authored — UBB never rewords an identifier it did not
# choose.
#
# BOTH DIRECTIONS, for the same reason the block above gives: two of these three
# are REQUEST properties, because a bag that is no longer stored must stop being
# part of what the contract accepts.
#
# WHAT THAT DOES *NOT* MEAN, STATED PLAINLY BECAUSE THE FIRST DRAFT OF THIS
# BLOCK GOT IT BACKWARDS. Removing the property from the schema does not make a
# stale caller's request fail. django-ninja keeps pydantic's `extra="ignore"`
# (pinned by `api/v1/tests/test_usage_dimensions.py`), so a caller still posting
# the retired bag gets a **200 and its labels are silently dropped** — they do
# not land in the surviving bag. Nothing is mis-metered and no money moves, but
# labels a caller believes it sent are not there.
#
# That is the same shape as #272's own request-side consequence and it is
# accepted on the same grounds: the pre-live window (ADR-0007 §5), and a
# migration path that is a one-line rename in the caller. It is recorded here
# rather than repaired because forbidding unknown fields is a whole-surface
# decision about every schema in the contract, which this ticket does not own.
# `test_a_stale_caller_is_accepted_and_its_labels_are_dropped` pins it.
#
# WHY THIS BREAK IS TAKEN NOW. The pre-live window is still open (ADR-0007 §5) —
# the launch tag is not what binds. The same drop after platform admission
# costs a 90-day deprecation cycle under ADR-0003 §4.
#
# NOT FLAGGED FOR SLICE 7, AND THE DISTINCTION IS DELIBERATE. Slice 7 owns the
# GROUPING vocabulary that still reads keys out of this bag — the keyed
# analytics parameter, the keyed margin breakdown and the key-driven invoice
# line labels (`g7-backend-tag_key`, `g7-backend-usage_line_item_group_by`).
# None of those three surfaces changed shape here; only the column beneath them
# moved. Slice 2 folded the field, slice 7 migrates the capability.
GET /api/v1/metering/usage/{event_id} removed the optional property `tags` from the response with the `200` status
POST /api/v1/metering/usage removed the request property `tags`
POST /api/v1/metering/usage/batch removed the request property `events/items/tags`
