# THE SECOND OPEN BAG, FOLDED INTO THE FIRST (#273, slice 2).
#
# A MOVE, NOT A RETIREMENT, and that is the whole difference from the block
# above. The unit total had nowhere to go, so it died. This one had somewhere:
# the same posting already carried an open bag, and the second one duplicated it
# under a name that advertised a capability the survivor deliberately does not
# have. A caller sends the same keys, to the same posting, under `metadata` —
# and `usage/migrations/0033_the_second_open_bag_folds.py` carries every
# existing value across so nothing already recorded is lost.
#
# WHY THE NAME GOES WITH THE CAPABILITY. The survivor is FILTERABLE AND
# READABLE, NEVER GROUPABLE. The retiring name promised grouping, and an
# unbounded free-text keyspace that can become a chart is one that can drive an
# invoice line label. Keeping the name would keep advertising the thing the
# design refuses. The keys inside are the tenant's own and are stored and
# returned exactly as authored — UBB never rewords an identifier it did not
# choose.
#
# BOTH DIRECTIONS, for the same reason the block above gives: two of these three
# are REQUEST properties, because a bag that is no longer stored must stop being
# part of what the contract accepts.
#
# WHAT THAT DOES *NOT* MEAN, STATED PLAINLY BECAUSE THE FIRST DRAFT OF THIS
# BLOCK GOT IT BACKWARDS. Removing the property from the schema does not make a
# stale caller's request fail. django-ninja keeps pydantic's `extra="ignore"`
# (pinned by `api/v1/tests/test_usage_dimensions.py`), so a caller still posting
# the retired bag gets a **200 and its labels are silently dropped** — they do
# not land in the surviving bag. Nothing is mis-metered and no money moves, but
# labels a caller believes it sent are not there.
#
# That is the same shape as #272's own request-side consequence and it is
# accepted on the same grounds: the pre-live window (ADR-0007 §5), and a
# migration path that is a one-line rename in the caller. It is recorded here
# rather than repaired because forbidding unknown fields is a whole-surface
# decision about every schema in the contract, which this ticket does not own.
# `test_a_stale_caller_is_accepted_and_its_labels_are_dropped` pins it.
#
# WHY THIS BREAK IS TAKEN NOW. The pre-live window is still open (ADR-0007 §5) —
# the launch tag is not what binds. The same drop after platform admission
# costs a 90-day deprecation cycle under ADR-0003 §4.
#
# NOT FLAGGED FOR SLICE 7, AND THE DISTINCTION IS DELIBERATE. Slice 7 owns the
# GROUPING vocabulary that still reads keys out of this bag — the keyed
# analytics parameter, the keyed margin breakdown and the key-driven invoice
# line labels (`g7-backend-tag_key`, `g7-backend-usage_line_item_group_by`).
# None of those three surfaces changed shape here; only the column beneath them
# moved. Slice 2 folded the field, slice 7 migrates the capability.

# 2026-08-11 THE MEASURED-QUANTITY BAG TAKES THE CANONICAL MEASUREMENT NAME
# (#274, slice 2; PR #302). Decision reference: ADR-0007 §1 and §3, and the slice
# spec's §F. The four lines below were EMITTED by the gate itself
# (`python openapi/contract_gate.py --baseline origin/main --emit`, oasdiff
# v1.23.0) and pasted unedited, per ADR-0007 §4 — everything above them is the
# human metadata that section permits.
#
# A RENAME, and the third distinct shape in three blocks: the unit total had
# nowhere to go and died, the second open bag folded into the first, and this one
# keeps its column, its contents and its meaning and changes only what it is
# called. `usage/migrations/0034_the_measured_quantities_take_the_canonical_name
# .py` is a single `RenameField` — no row moves and nothing is recomputed.
#
# WHY THE NAME. The keys in this bag are keys INTO the Measurement declarations
# an Event Type carries, and the field now says so. That is what separates a
# quantity that can be costed from one that is merely carried, and it is the same
# word the declarations already publish (`GET /event-types/{key}/measurements`).
# On the detail response it also closes a gap #271 opened three tickets ago:
# `measurements_status` landed there under this name while the bag it describes
# still carried the other one, so a reader had to be told the two were about the
# same thing. They now read as the pair they always were.
#
# BOTH DIRECTIONS, for the reason the blocks above give: two of these four are
# REQUEST properties, because a name the server no longer stores under must stop
# being part of what the contract accepts.
#
# WHAT A STALE CALLER GETS, AND WHY THIS ONE IS THE EXPENSIVE CASE. django-ninja
# keeps pydantic's `extra="ignore"`, so a caller still sending the retired key is
# NOT refused: it gets a 200 and its quantities are dropped. Where #273's fold
# above lost labels and moved no money, everything the pricing engine prices from
# lives in THIS bag — so a caller relying on server-side pricing is charged as
# though it measured nothing, and the posting records saying so. Both halves are
# pinned rather than left to a support ticket:
# `test_the_measured_quantities_take_the_canonical_name.py` takes the 200 and the
# dropped bag, and `test_record_usage_pricing.py` runs it against a real cost card
# and takes the zero.
#
# RECORDED RATHER THAN REPAIRED, on #273's grounds exactly: refusing unknown
# fields is a decision about every schema on the contract, which one field on
# three schemas does not own. The pre-live window is what makes the break free
# (ADR-0007 §5 — the launch tag is not what binds), the same rename after platform
# admission costs a 90-day deprecation cycle under ADR-0003 §4, and the caller's
# migration is one line.
#
# NO BEHAVIOUR MOVED WITH THE NAME. The bag's only validation is that its values
# are not negative, and that validator crossed unchanged. A quantity no
# declaration matches is still accepted here and still contributes nothing to the
# amounts beside it; making that visible instead of silent is slice 3's, and this
# ticket deliberately leaves it alone so the next reader does not read the rename
# as the fix.
GET /api/v1/metering/usage/{event_id} removed the optional property `usage_metrics` from the response with the `200` status
POST /api/v1/metering/usage removed the optional property `usage_metrics` from the response with the `200` status
