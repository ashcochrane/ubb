# Reviewed contract breaks, ERR level — cumulative since `api-v1-launch`.
#
# The gate (`python openapi/contract_gate.py`, run by CI) compares the spec at
# the immutable `api-v1-launch` tag against the working tree. So this file
# answers one question: has every break since the contract was published been
# reviewed? Each entry below is one break that has.
#
# THREE RULES — the reasoning behind each is in openapi/README.md:
#
#  1. Entries are GENERATED, never hand-typed:
#         python openapi/contract_gate.py --baseline origin/main --emit
#     Hand-derivation once put seven WARN-level lines in this file, where
#     `--err-ignore` silently did nothing for them, and missed two ERR findings
#     entirely. An entry that suppresses nothing now turns the gate red.
#  2. ERR-level findings ONLY — WARN-level ones live in the sibling
#     oasdiff-warn-ignore.txt. The two flags filter by level before matching
#     text, so a line in the wrong file is a no-op, not a near-miss.
#  3. Human metadata belongs on `#` comment lines: slice, date, pull request,
#     decision references, and why the break is accepted. A non-comment line
#     that is not a generated finding matches nothing, and the gate says so.
#
# THIS FILE CANNOT REACH ZERO while the baseline is `api-v1-launch`. The
# differences from that tag are real and intentional, and they accumulate as
# each slice lands. It clears only when slice 8 tags a NEW baseline and the gate
# is pointed at it (migration/cutover decision §7.5); `api-v1-launch` itself is
# never moved or deleted. This is a DIFFERENT MECHANISM from the
# implementation-rule migration ledgers, which are seeded with today's known
# violations and must shrink to empty by slice 8. Growing-and-intentional vs
# shrinking-and-defective — do not conflate them.
#
# So never delete an entry to make this file shorter. Delete one only when the
# gate reports it INERT, which means it no longer describes a real break and has
# become a lie; regenerate rather than edit it by hand.
#
# WHAT MAY BE ADDED. Because the baseline *is* the launch tag, every entry here
# is by construction a post-launch break; the pre-launch lane that the old
# `LAUNCH TAG BOUNDARY` marker separated cannot appear in this comparison at
# all, so the marker is gone. Its 20 pre-tag entries (#78, #86) went with it:
# the tag already contains those changes, so they matched nothing and the gate
# reported them inert. They remain in git history (see #195, which installed the
# cumulative comparison). A NEW entry is permitted only:
#   - in the PRE-LIVE LANE — no tenant is integrated against v1, so the break is
#     hand-coordinated with the one known consumer. docs/api-compatibility.md
#     carries the dated note and names the day it is deleted; the re-model's
#     licence is #137 constraint 1, reaffirmed by migration/cutover §7.1; or
#   - as evidence of an ADR-003 §4 DEPRECATION already in flight: `deprecated:
#     true` on the operation, a runtime `Sunset` header (register the route in
#     api/v1/deprecation.py), a dated changelog entry + email announcement, and
#     at least 90 days' notice (a floor we may raise, never lower).
# From the first live tenant, only the second remains. A bare removal or rename
# is a contract breach, not a CI escape hatch. See docs/api-compatibility.md.

# ...and the narrowing (#240). `tenant_product` is a CLOSED concept — UBB owns
# the whole value set — and the tenant model now imports it from the generated
# `core.vocabulary` instead of restating it. That is what licenses the contract
# to say so: the export advertises a concept's values only where the backend
# already serves them (#208), so the enum below cannot appear on a field that
# still accepts something else. The value set is written at export time from
# openapi/known-values.json; neither schema spells a value.
#
# This is a NARROWING of a field that was `type: string` with no constraint —
# and it is a narrowing of the DOCUMENT, not of the runtime. Nothing here adds
# a second enforcement point: `json_schema_extra` renders the enum and does not
# validate, and typing the field `Literal[...]` is forbidden outright
# (docs/conventions/api-contract.md — "a second copy of a value set the
# registry owns"). An unknown product is refused where it always was, by the
# model, as `422 invalid_config`.
#
# That is the change worth having. The set the contract ADVERTISES and the set
# the backend ENFORCES are now the same set by construction — both are the
# registry's, one rendered at export time and one imported at
# `apps/platform/tenants/models.py` — where before, the contract advertised
# nothing and a client had to discover the vocabulary by being rejected.
# `test_tenant_endpoints.py` pins the refusal that survives.
#
# It is also the first `x-ubb-concept` marker in the committed contract, and
# the reason the marker-driven half of G4 stops being vacuous.
#
# ONLY THE REQUEST SIDE APPEARS. The same enum lands on the response schema
# (`TenantConfigOut.products`) in this commit and oasdiff reports nothing for
# it, correctly: a server promising FEWER values than before cannot break a
# reader. Do not go looking for a second line to pair with this one.
PATCH /api/v1/tenant/config request property `products/anyOf[subschema #1]/items/` was restricted to a list of enum values

# 2026-08-12 THE RATE'S QUANTITY NAME TAKES THE CANONICAL MEASUREMENT NAME
# (#275, slice 2). Decision reference: ADR-0007 §1 and §3, and the slice spec's
# §F3. The four lines below were EMITTED by the gate itself
# (`python openapi/contract_gate.py --baseline origin/main --emit`, oasdiff
# v1.23.0) and pasted unedited, per ADR-0007 §4 — everything above them is the
# human metadata that section permits. Read this block together with the two
# WARN-level lines in the sibling file: same rename, same commit, split only by
# level.
#
# THIS ONE REFUSES A STALE CALLER INSTEAD OF IGNORING IT, and that is the whole
# reason to read the block rather than skim it. The three retirements before it
# (#272, #273, #274) all dropped OPTIONAL properties, so django-ninja's
# `extra="ignore"` left a stale caller with a 200 and quietly missing data — the
# expensive, quiet failure their blocks argue about at length. The property
# renamed here is REQUIRED on both write endpoints. The retired key is thrown
# away, the canonical one is then absent, and the request is refused at
# validation with **nothing written**. That is why two of these four findings are
# `added the new required request property` — a shape oasdiff has not reported
# for any earlier slice-2 break.
#
# So the migration cost lands loudly, at the caller's first attempt, on a
# management surface a human drives. Nothing is mis-priced in the meantime: a
# rate that fails to write does not exist, and events are priced by the rates
# that do. `test_the_rates_quantity_name_takes_the_canonical_name.py` pins the
# refusal AND its control, so "refused for the right reason" is distinguishable
# from "refused for any reason".
#
# WHY THE NAME. This column names WHICH declared quantity a rate prices, and the
# retired word named the metered entity rather than the quantity inside it —
# #145 §10's mis-translation, at the integration boundary where it costs most.
# The canonical word is already the tree's name for a free-text quantity key
# (the quarantine record has carried it since #265) and already the word the
# declarations publish (`GET /event-types/{key}/measurements`).
#
# THE NAME IS FINAL; THE IMPLEMENTATION IS NOT. It is still free text after this
# commit, and slice 3 replaces it with a reference to the declared record. That
# is ADR-0007 §3 exactly — final name, final contract, implementation partly
# built — and it is what stops this published property being renamed a SECOND
# time when the reference arrives. Slice 3 changes what the value must satisfy,
# not what it is called, so no further break is owed for it.
#
# WHY THE BREAK IS TAKEN NOW. The pre-live window is still open (ADR-0007 §5 —
# the launch tag is not what binds). The same rename after platform admission
# costs a 90-day deprecation cycle under ADR-0003 §4, and the caller's migration
# is one line.
#
# FLAGGED FOR SLICE 4. The rate entity itself is rebuilt there, and its own
# retired vocabulary — the cost/price discriminator, the book reference and the
# shape-of-charge column, all still visible in these findings' neighbours — is
# that slice's to pay. Renaming this column at slice 2 anyway is not an
# oversight: the ledger owns it here, and an owner may move earlier, never later.
